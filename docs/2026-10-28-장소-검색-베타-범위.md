# 장소 검색과 베타 서비스 범위

2026-10-28. 출발지·목적지를 시연 장소 3곳 대신 검색으로 고를 수 있게 했다. 베타 버전은 서울 용산구 안에서만 추천한다. 범위 밖 장소를 고르면 alert로 안내하고 선택하지 않는다.

## 흐름

`출발지/목적지 선택 → 검색창(250ms 디바운스) → GET /v1/places/search → 결과 선택`

- 검색어가 없으면 기존 시연 장소 3곳을 빠른 선택으로 보여준다.
- 범위 밖 결과에는 "베타 지역 밖" 표시가 붙는다. 이 결과를 누르면 "베타 서비스 지역이 아니에요 / DALRO 베타 버전은 서울 용산구 안에서만 코스를 추천해요." alert가 뜨고 모달은 그대로 남는다. 웹은 `window.alert`, iOS/Android는 `Alert.alert`를 쓴다(react-native-web의 `Alert`는 표시되지 않음).
- 범위 안이어도 300m 안에 달릴 도로가 없으면 별도 안내를 띄운다.
- 선택하면 장소 좌표 대신 서버가 준 **도로 위 출발 지점**(`start_position`)과 장소 이름을 조건에 저장한다. 추천 요청에 `start_label`/`end_label`(선택 필드)로 이름을 보내고, 코스 이름표에 그대로 쓴다.
- 서버도 용산구 경계 밖(50m 여유) 요청을 `422`로 거부한다. 앱은 서버의 안내 문장(`detail`)을 오류 화면에 그대로 보여준다.

## 결정

1. **검색은 서버가 한다.** 카카오 REST 키는 비밀값이라 앱 번들(`EXPO_PUBLIC_*`)에 넣을 수 없다. 키는 `server/.env.local`의 `KAKAO_REST_API_KEY`에 둔다.
2. **키가 없어도 검색이 된다.** 노션 자료로 서울 도로명 14,073개, 공원 1,584개, 자치구 25개 로컬 색인을 만들었다. 범위 밖 장소도 검색되므로 베타 안내를 시연할 수 있다. 역·건물·상호 이름은 카카오 키가 있어야 찾는다.
3. **베타 범위는 용산구 행정경계다**(`seoul_district_boundary_5186`, 기준일 2025-06-30). 목적에 관계없이 같은 범위를 쓴다.
4. **mock 모드는 고정 목록을 검색한다.** 용산구 주요 장소 9곳과 서울 장소 5곳이다. 좌표는 대략값이고, 범위 포함 여부와 출발 도로 지점은 실제 경계·도로망으로 계산해 넣었다([src/data/places.ts](../src/data/places.ts)).
5. **더미 코스 ID에 검색 좌표를 넣는다.** 시연 장소는 기존처럼 `ichon` 등을 쓴다. 검색한 장소는 `c126973032_37534738`(마이크로도 정수)를 쓴다. 장소마다 ID가 달라 캐시가 섞이지 않고, 새로고침해도 같은 코스가 복원된다. 점(.)을 쓰지 않는 이유는 로컬 정적 서버가 점이 든 경로를 파일로 보고 404를 내기 때문이다. 이름은 ID에 없어서, 새로고침 후에는 "선택한 출발지"로 표시된다.

## 검증

- 서버 pytest 18개(검색 4개 추가: 로컬 검색·범위 표시·카카오 응답 모사·카카오 실패 대체·범위 밖 추천 422)
- 앱 vitest 63개(서버/더미 분기, 시연 검색, 좌표 ID 복원, HTTP 검색 검증과 서버 안내 문장, 장소 이름 표시)
- Playwright 20개(모바일·데스크톱 각각: 강남 검색 → alert → 삼각지역 선택 → 추천 → 상세 새로고침)
- hybrid 웹 + 실서버를 Chrome으로 확인했다. "강남" 검색 결과가 모두 베타 지역 밖으로 표시되고, 선택하면 alert가 1회 뜬다. "효창원로"를 선택하면 실데이터 PACE 3개가 나오고 이름표가 "효창원로"다. 페이지 오류는 없었다.
- 카카오 로컬 API는 키가 없어 실제 호출을 확인하지 못했다. 응답 형식은 모사 테스트로만 검사했다.
