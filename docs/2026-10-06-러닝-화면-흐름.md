# 목적 선택부터 결과까지의 화면 흐름

사용자가 첫 화면에서 할 일은 러닝 목적 하나를 고르는 것이다. 홈의 지도, 추천 목록, 조건 선택을 분리하고 아래 흐름으로 정리했다.

`런닝 홈 → Loop / Straight 방식 선택 → 코스 설정 → 추천 코스 → 러닝 준비 → 모의 러닝 → 결과 → 기록 저장`

- 런닝 홈(`/`): PACE / POWER / NIGHT / GREEN 카드 4개. 출발지·거리·시간대 요약에서 조건 설정으로 바로 갈 수 있다. 나의 러닝 카드에는 저장한 모의 러닝 수·누적 거리와 기록/저장 코스 바로가기를 제공한다. 기록이 없으면 첫 러닝 안내를 보여준다. 최근 저장한 코스와 진행 중 세션, 저장 전 결과가 있을 때만 해당 행동을 표시한다. NIGHT를 고르면 야간, 다른 목적을 고르면 주간으로 시작한다.
- 러닝 방식(`/route-type`): 목적 선택 후 별도 페이지에서 Loop(출발지로 돌아오기) / Straight(목적지까지 달리기) 두 카드 중 하나를 고른다.
- 코스 설정(`/explore`, `app/explore.tsx`): 탭 바깥의 화면이다. Loop는 용산구 출발지와 3/5/7/10km 및 직접 입력(1~20km, 최대 소수점 세 자리)을 정한다. Straight는 출발지·목적지를 각각 고르고 거리는 자동 계산한다. 두 지점을 교환할 수 있고 같은 장소는 반대쪽 후보에서 비활성화한다. 주야간은 공통이다. 마지막 `코스 추천받기`에서 추천 화면으로 이동한다. 기존 8km 조건도 직접 입력으로 복원한다.
- 추천(`/recommendations`): 지도에 세 후보를 표시하고 가로 카드, 추천 번호 선택, 지도 경로 선택을 동기화한다. 이유는 한 문장, 환경 지표는 거리·시간·경사·신호·환경 점수만 보여준다.
- 준비(`/course/[id]`): 지도, 예상 거리/시간, 출발지→목적지(Loop는 출발지 회귀), 코스 저장, `러닝 시작`. 기존 URL과 저장한 코스는 그대로 접근할 수 있다.
- 주행(`/run`): 지도, 시간·거리·현재/평균 페이스, 일시정지. 정지 시 계속하기/종료가 나타난다. 완주는 자동 정지한다. 시연 컨트롤은 펼쳐서 사용한다. 모의 이동은 일정 속도이므로 현재와 평균 페이스가 같고, 실제 GPS를 수집하지 않는다. 지도는 모의 위치를 보간하고 주행한 구간과 남은 구간을 다른 색으로 표시한다. 웹 카카오는 흰색이 주행한 구간이며, 도식/native는 녹색이 주행한 구간이다.
- 결과(`/result?id=…`): 모의 거리·시간·페이스, 지도, 선택한 전체 코스의 환경 리포트. 환경 점수는 기존 `environment_score`이며 실제 적합도·안전·주행 분석 점수로 재해석하지 않는다. 중도 종료면 일부 주행임을 표시한다.
- 기록(`/records`): 저장한 기록 목록과 누적 거리. 기록을 누르면 결과 화면으로 이동한다. 이전 `/records?id=…` URL도 결과로 연결한다.
- 마이(`/profile`): 기록 합계, 저장한 코스(`/saved`), 최근 목적, 데모 프로필 정보.
- 탭: **기록 / 런닝(홈) / 마이**. 가운데 런닝 탭에 녹색 원형 시작 아이콘을 사용한다. 앱은 런닝 홈에서 시작하며, 가운데 탭을 누르면 목적 선택 홈으로 돌아온다.

## 시연 범위와 상태

현재 위치·주소 검색은 연결하지 않는다. 출발지·목적지는 이촌 한강공원 / 남산 둘레길 / 용산가족공원의 시연 장소에서 고른다. Straight는 실제 두 좌표를 연결하는 열린 더미 경로이며 최단거리 직선이라는 뜻은 아니다. 실제 추천과 GPS를 구현한 것으로 표현하지 않는다.

mock 추천은 선택 목적의 세 후보를 반환한다. 목적별 기본 모양과 환경 예시가 다르고, 같은 목적 내 후보는 회전·거리 편차로 구분한다(`mock-route-types-v3`). 실제 도로망 탐색은 아니다. HTTP 저장소와 Zod 계약, `RouteMapProps` 및 카카오 공급자 경계는 유지한다. 새 거리의 상세 URL을 새 mock 저장소에서도 복원한다. 도식 지도는 화면 비율에 맞춰 경로를 배치해 세로 화면에서 잘리지 않게 한다. JS 전달 선을 주행 구간/남은 구간으로 분리한다. 웹·도식·native 지도에서 Straight의 출발·도착을 구분한다. Native 전달 데이터에 선택 코스의 실제 끝점 `end`를 추가하고 iOS/Android 모듈이 도착 마커를 그린다. 진행률이 달라져도 목적지는 이동하지 않는다.

`finish()`는 시연 결과를 `draft`로 만들고 세션을 종료한다. `save(id)`를 누르면 기록 목록에 한 번만 추가한다. 저장 전 결과도 로컬 보관해 새로고침을 지원한다. 같은 코스를 다시 달리면 결과를 저장한 후 준비 화면으로 간다. 저장하지 않고 홈으로 가는 명시적 버튼도 있다. 저장 전 결과나 세션이 있으면 새 세션이 덮어쓰지 않는다. 기존 `dalro-records-v1` 기록/후기는 보존한다. 진행 중 세션은 앱 재시작 시 복원하지 않는다.

## 검증

계약 경계·직접 입력·URL 복원·일시정지·완주·저장/중복 방지 테스트와 모바일/데스크톱 E2E를 갱신했다. 실행 결과와 실행 방법은 `DEMO.md`를 참고한다. Native 마커 변경은 개발 앱을 새로 빌드해야 적용된다. 로컬 preflight에서 Xcode/iPhoneOS SDK와 Android SDK가 없어 컴파일·실기 확인은 하지 못했다. iOS/Android JS export는 APK/IPA 빌드나 실제 기기 테스트가 아니다.
