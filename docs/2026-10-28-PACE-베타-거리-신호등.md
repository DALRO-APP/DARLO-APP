# PACE 베타 잠금 · Straight 거리 · 신호등 표시

2026-10-28. 베타에서는 PACE만 새 추천을 받을 수 있다. 홈의 POWER·NIGHT·GREEN 카드는 흐리게 표시하고 자물쇠·베타 준비 중 배지를 붙여 선택을 막았다. Zustand 업데이트와 저장 조건 복원도 새 추천의 목적을 PACE로 고정한다. 기존 장소·주야간·거리·즐겨찾기와 과거 기록은 보존한다. 서버·계약의 다른 목적 정의는 후속 구현을 위해 유지한다.

Straight 설정의 자동 거리 안내 칸을 실제 첫 번째 추천 코스의 `summary.distance_m`을 소수 한 자리 km로 표시하는 예상 거리 카드로 바꿨다. `useRecommendations`를 Straight에서만 활성화하고 추천 화면과 같은 TanStack Query 키·60초 캐시를 사용한다. 장소·방향·시간대를 바꾸면 새 조건으로 계산하며 이전 조건의 거리를 남기지 않는다. 계산 중·오류/재시도·빈 결과를 표시한다. 거리 값을 Zustand나 `target_distance_m`에 복제하지 않으며 Straight 요청의 목표 거리는 계속 null이다. mock 모드에서는 더미 코스 기준임을 표시한다. 미리보기도 기존 추천 API를 사용하므로 서버에 코스·추천 기록이 저장된다.

서버는 경로 선이 신호 부착대 원본 도형과 실제로 교차하는 경우만 `signal_positions`로 반환한다. 버퍼·스냅·근접 허용 오차는 사용하지 않는다. 원본과 경로의 교차점 하나를 시설별로 선택한 뒤 EPSG:5186에서 EPSG:4326으로 변환한다. 화면에 그리는 경위도 경로를 동일하게 역투영해 판정하므로 추천과 저장 코스 상세의 기준이 같다. 같은 길을 반복해도 시설별 한 번만 센다. `null`은 자료 없음, `[]`는 교차 지점 0개, 필드 생략은 이전 응답이다. 같은 도로망 버전의 저장 코스는 상세 조회마다 현재 교차 기준으로 위치를 보완해 이전 버퍼 위치가 남지 않게 한다. DB 스키마 변경이나 재임포트는 필요하지 않다.

`summary.signal_count`와 기존 추천 비용·환경 근거의 10m 주변 시설 통계는 유지한다. 지도 범례는 이를 구분해 **통과 신호등**으로 표시하며, 교차 지점 수는 주변 시설 수 이하일 수 있다.

기본 공간정보 지도는 **선택한 추천 코스 선과 교차하는 신호등**을 빨간 점으로 표시한다. 추천 1·2·3을 바꾸면 점과 개수도 바뀐다. 신호 부착대 자료이므로 교차로 수나 현재 빨간불을 뜻하지 않는다. 위치가 없는 더미 코스에는 임의로 점을 만들어 표시하지 않는다. 기존 선택형 native 카카오 SDK에는 이번 마커 기능을 추가하지 않았다.

## 실행과 검증

```sh
# 서버 코드 변경 반영: 기존 서버를 종료한 다음 server/에서 실행
.venv/bin/uvicorn dalro_api.main:app --host 0.0.0.0 --port 8000
# 앱 루트, 다른 터미널
EXPO_PUBLIC_DATA_SOURCE=hybrid EXPO_PUBLIC_API_URL=http://localhost:8000 npm run web -- --clear
```

- 앱 `npm run check`: 70개 단위 테스트·타입·lint·자료 계약·명령 가드 통과.
- 서버 pytest: 24개 통과. 정확한 교차·1mm 옆 평행선/점 제외·중복 방지·선형 시설·미측정·추천/상세/이전 저장 코스 보완 포함.
- 웹 E2E: 모바일·데스크톱 18개 통과, 기본 공급자가 공간정보 지도라 카카오 전용 6개는 기존 조건에 따라 생략.
- 웹·iOS·Android JS export 통과. APK/IPA 빌드·실제 기기 검증은 하지 않았다.
- 이전 10m 표시 기준의 실서버 19/30/8개 확인은 사용자 수정 요청으로 폐기했다. 정확한 교차 기준으로 재시작한 서버에서 이촌 5km 후보 3개는 모두 교차점 0개다. 주변 통계 19/30/8개는 유지하며 지도에는 빨간 점을 표시하지 않는다. 추천과 상세 응답이 같은 기준임을 확인했다.
