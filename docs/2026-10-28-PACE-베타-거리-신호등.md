# PACE 베타 잠금 · Straight 거리 · 신호등 표시

2026-10-28. 베타에서는 PACE만 새 추천을 받을 수 있다. 홈의 POWER·NIGHT·GREEN 카드는 흐리게 표시하고 자물쇠·베타 준비 중 배지를 붙여 선택을 막았다. Zustand 업데이트와 저장 조건 복원도 새 추천의 목적을 PACE로 고정한다. 기존 장소·주야간·거리·즐겨찾기와 과거 기록은 보존한다. 서버·계약의 다른 목적 정의는 후속 구현을 위해 유지한다.

Straight 설정의 자동 거리 안내 칸을 실제 첫 번째 추천 코스의 `summary.distance_m`을 소수 한 자리 km로 표시하는 예상 거리 카드로 바꿨다. `useRecommendations`를 Straight에서만 활성화하고 추천 화면과 같은 TanStack Query 키·60초 캐시를 사용한다. 장소·방향·시간대를 바꾸면 새 조건으로 계산하며 이전 조건의 거리를 남기지 않는다. 계산 중·오류/재시도·빈 결과를 표시한다. 거리 값을 Zustand나 `target_distance_m`에 복제하지 않으며 Straight 요청의 목표 거리는 계속 null이다. mock 모드에서는 더미 코스 기준임을 표시한다. 미리보기도 기존 추천 API를 사용하므로 서버에 코스·추천 기록이 저장된다.

서버는 경로 선에서 **2m 이내**에 있는 신호 부착대 위치를 `signal_positions`로 반환한다. 완전 교차만 판정하면 도로 중심선과 시설 좌표 차이 때문에 실데이터가 0개가 되어, 사용자의 후속 요청에 따라 좁은 버퍼를 적용했다. `SIGNAL_MARKER_BUFFER_M=2.0`으로 거리 조건을 고정하고 더 멀리 있는 시설은 제외한다. 원본이 선형이면 코스에 가장 가까운 원본 위 점을 사용하며, 시설 좌표를 경로 위로 억지로 옮기지 않는다. EPSG:5186에서 판정한 뒤 EPSG:4326으로 변환한다. 같은 길을 반복하거나 같은 횡단보도에 신호 부착대가 여러 개 있어도 중복 표시하지 않는다. `null`은 자료 없음, `[]`는 2m 안 시설 0개, 필드 생략은 이전 응답이다. 같은 도로망 버전의 저장 코스는 상세 조회마다 현재 기준으로 위치를 보완한다. DB 스키마 변경이나 재임포트는 필요하지 않다.

`summary.signal_count`와 기존 추천 비용·환경 근거의 10m 주변 시설 통계는 유지한다. 지도 범례는 이를 구분해 **신호등 N곳**으로 표시하며, 2m 내 표시 개수는 기존 10m 주변 시설 수 이하일 수 있다.

기본 공간정보 지도는 **선택한 추천 코스 2m 안 신호등**을 빨간 점으로 표시한다. 추천 1·2·3을 바꾸면 점과 개수도 바뀐다. 신호 부착대 자료이므로 교차로 수나 현재 빨간불을 뜻하지 않는다. 위치가 없는 더미 코스에는 임의로 점을 만들어 표시하지 않는다. 기존 선택형 native 카카오 SDK에는 이번 마커 기능을 추가하지 않았다.

## 실행과 검증

```sh

.venv/bin/uvicorn dalro_api.main:app --host 0.0.0.0 --port 8000
# 앱 루트, 다른 터미널
EXPO_PUBLIC_DATA_SOURCE=hybrid EXPO_PUBLIC_API_URL=http://localhost:8000 npm run web -- --clear
```

- 앱 `npm run check`: 70개 단위 테스트·타입·lint·자료 계약·명령 가드 통과.
- 서버 pytest: 24개 통과. 2m 경계 포함·2.001m 바깥 제외·중복 방지·선형 시설·미측정·추천/상세/이전 저장 코스 보완 포함.
- 웹 E2E: 모바일·데스크톱 18개 통과, 기본 공급자가 공간정보 지도라 카카오 전용 6개는 기존 조건에 따라 생략.
- 웹·iOS·Android JS export 통과. APK/IPA 빌드·실제 기기 검증은 하지 않았다.
- 실데이터 이촌 5km 후보에서 1/2/3/5/10m 거리별 시설 수를 비교했다. 묶기 전 2m 원본 시설은 추천 1·2·3에 각각 4/3/0개이며, 10m 주변 통계 19/30/8개와 구분한다.

## 웹 SVG 이벤트 경고 수정

`react-native-svg` 15.15.4의 웹 구현은 `G.onPress`에 native touchable mixin을 연결해 `onResponderTerminate` 등을 DOM에 전달한다. 웹 React에서 이 속성이 무시된다는 콘솔 경고가 발생했다. `RouteLineGroup.web.tsx`는 DOM `<g onClick>`을 사용하고, native 구현은 기존 SVG `G.onPress`를 사용하도록 분리했다. 라이브러리나 node_modules는 수정하지 않는다. 지도 선 클릭으로 후보를 선택하는 동작을 유지하며, E2E에서 코스 선 클릭과 responder 콘솔 경고를 검사한다.

추가 검증: 실제 Expo 개발 모드의 Chrome 모바일·데스크톱에서 responder 경고 없음·지도 선 클릭·추천별 신호등 4/3/0개를 확인했다. 갱신한 지도 E2E 2개, 앱 검사 70개, 서버 테스트 24개, 웹·iOS·Android JS export가 통과했다. 기존 pointerEvents 사용 중단 예고 경고는 이번 responder 오류와 별개이며, 실제 기기 검증은 수행하지 않았다.

## 지도 안내 간소화

하단의 `DEM 5m · 도로망 · 실데이터 코스 · 인접 신호등` 설명을 제거하고, `신호등 N곳` 배지를 지형·도로망·경사 레이어 버튼 바로 아래로 옮겼다. 신호등 위치 자료가 없는 더미 코스에는 개수 배지를 표시하지 않는다. 표시 기준은 최종 2m로 줄였다.

이번 UI 간소화와 2m 변경은 타입 검사 및 서버 pytest 24개로 확인했다.

## 같은 건널목의 신호등 묶기

먼저 경로 2m 이내 신호만 고른다. 원본 횡단보도 도형과의 거리가 5m 이내면 가장 가까운 횡단보도에 연결하고 같은 횡단보도당 한 점으로 표시한다. 다른 횡단보도에 연결된 신호는 서로 가까워도 합치지 않는다. 횡단보도에 매칭되지 않은 점끼리는 묶음의 모든 점과 10m 이내일 때만 합친다. 따라서 점이 이어진다는 이유로 교차로 전체를 하나로 합치지 않는다. 원본 신호 중 묶음 중심에 가까운 점을 대표 위치로 사용하므로 경로 2m 조건을 유지한다.

이는 신호 표시 지점의 중복을 줄이는 기준이며, 횡단보도 매칭이 없는 근접 묶음까지 실제 건널목 하나라고 확정하는 것은 아니다. 원본 시설 수와 추천 비용은 유지한다. 회귀 테스트는 같은 횡단보도의 양쪽 부착대, 인접한 다른 횡단보도 분리, 중복 좌표, 연쇄 병합 방지, 입력 순서 독립성을 확인한다.

검증: 서버 pytest 26개 통과. 재시작한 실서버의 이촌 5km 추천 1·2·3은 중복 제거 후 3/2/0곳으로 표시되며 추천·상세 응답이 일치했다.
