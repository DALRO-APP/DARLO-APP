# 경사 결측과 보행 불가 구간 서버 검증

검증일: 2026-11-18. 팀 [QGIS 검증 자료](https://app.notion.com/p/3e78ae567af28033b190ea17aae5409b)의 엑셀 2개·원본 경사 통계 DBF·검증 도로망 GPKG·로컬 SQLite·고정 배포 seed·현재 배포 `/api/health`를 대조했다. 요청한 [체크 페이지](https://app.notion.com/p/41c8ae567af280f88135e9bffc183d00)에 결과를 전달한다.

**현재 배포 서버는 보정 전 버전이다. 이번 수정은 로컬에 구현·검증했으며 배포하지 않았다.**

## 1. 확인 결과

| 항목 | 실제 확인 |
|---|---|
| 원본 경사도 통계 | `용산구_전처리.zip`의 `도로 통계.dbf`, 4,497개 |
| 원본 `slope_mean=NULL` | 20개. `slope_missing_20.xlsx`와 OSM ID 집합 일치 |
| 최종 도로망과 매칭 | 18개 원본 피처. `DALRO_slope_missing_final_18.xlsx`와 OSM ID 집합 일치 |
| 서버 탐색 간선으로 분할 | 18개 피처 → 42개 `edge_id`, 총 408.15m |
| 기존 서버 DB 속성 | 42개 모두 `slope_deg=0`, `slope_norm=0` |
| 기존 계산 | `slope_norm=None`일 때만 1.0 적용. 해당 42개는 경사 항이 0으로 계산됨 |
| 매칭되지 않은 OSM ID | `331947399`, `781192801` |
| 기존 0인 간선 | 124개. 검증으로 결측이 확인된 42개만 보정, 나머지 82개는 0 유지 |

따라서 “결측에 최대 패널티 적용”이라는 코드의 의도는 있었지만, upstream에서 NULL이 0으로 바뀐 해당 구간에는 실제로 적용되지 않았다. 신호·횡단보도의 시설 없음 `NULL→0` 정책을 경사 미측정에도 적용하면 안 된다.

`DALRO_slope_missing_final_18.xlsx`의 fid는 추출 레이어에서 새로 붙은 값이다. 이 fid를 서버의 `source_fid`로 쓰지 않고, `osm_id`와 원본 검증 GPKG의 fid를 대조해 고정했다.

## 2. 버전과 원본

- 현재 배포 health·로컬 DB·고정 seed의 기준 버전: `yongsan-verified-988cb48a`.
- 파일: `검증된_용산구_도로망.zip/05_team_share/yongsan_running_roads_final_verified.gpkg`.
- 피처 4,426개 → 탐색 간선 9,276개·노드 6,906개. EPSG:5186 원본, API는 EPSG:4326.
- GPKG SHA-256: `988cb48aa0f67d9d70eed7701623199cc351c9f8ecfb969e346c5529fba47697`.
- `988cb48a`는 GPKG SHA-256 앞 8자리다. 원본 파일명이 아니라 파일 내용으로 버전을 붙였다.
- DB import 시각: `2026-10-28 10:28:51.308704 UTC`(KST 19:28:51). 이번 검증 때 새로 받은 Notion ZIP과 기존 로컬 원본 ZIP의 SHA-256도 일치한다.
- 신호·횡단보도 원본: `종설_기본망신호.zip`의 A057_L 부착대·A004_A 횡단보도. 가로등: `가로등공원_데이터_전처리.zip/yongsan_streetlight_5186`. 이 자료와 버퍼 폭은 이번에 바꾸지 않았다.
- 로컬 보정 적용 버전: `yongsan-verified-988cb48a-qc-20261118-v1`.

## 3. 적용한 보정

원본 GPKG·원본 SQLite·고정 SQL seed를 덮어쓰지 않는다. 공개 검토표 `server/seed/yongsan-quality-review.json`을 서버 그래프 로딩과 앱의 캐시 검증에 함께 사용한다.

- 기준 버전과 `(source_fid, osm_id)`가 모두 일치하는 18개 피처만 미측정으로 복원한다.
- 원격 배포에서는 공개 health의 버전·네트워크 통계를 확인했다. 배포 환경의 DB 행에 직접 접속한 것은 아니다. 현재 동일 버전인 고정 배포 seed에서는 해당 42간선이 모두 원본 0임을 별도로 검증했다.
- 그래프에서 지형 경사는 `null`, 비용 계산의 유효 `slope_norm`은 1이다. DB의 원본 0은 보존한다.
- 구간 패널티의 경사 항은 기존 대비 0.17 증가한다. α=3에서 구간 비용 증분은 `길이×0.51`이다. 신호 항·가중치 0.83/0.17·α=3·후보 정렬식은 유지한다.
- 미측정 구간을 지도 경사 레이어에서 평지로 표시하지 않도록 지도 파생 자료도 갱신했다. 전달용 export의 버전·경사·통행 값도 그래프와 맞췄다.
- health는 `data_version`(유효 버전), `base_data_version`(원본 버전), `quality_review`(보정 피처·간선 수·제외 ID)를 별도로 반환한다.
- 보정 이전의 결측 구간 코스와 보행 제외 간선 코스는 서버 상세에서 재추천을 요구한다(404). 앱 repository도 해당 HTTP 응답을 거부하고 해당 기기 캐시를 재사용하지 않는다. 무관한 기존 코스·기록은 유지한다.

## 4. 추천 2의 보행 불가 구간

팀의 표시 지도와 동일한 이촌 한강공원 Loop 5km·α=3 조건을 재현했다. 기존 추천 2는 **4,699m·경로 비용 5,398.66**으로 캡처의 **4.70km·5,399**와 일치한다.

| edge_id | osm_id | 도로 | 길이 m |
|---|---|---|---:|
| 2334-0 | 464445125 | 이촌로, 지하차도 접근 구간 | 363.06 |
| 1366-0 | 246253102 | 서빙고지하차도 | 121.12 |
| 1365-0 | 246253101 | 무명 연결 도로 | 134.39 |
| 1109-0 | 37403232 | 서빙고로51길 접속 구간 | 10.83 |

팀이 “보행 불가”라고 보고한 6~9번 구간에 대응하는 위 4개 간선, 총 **629.40m**를 추천에서 제외했다. 같은 OSM 도로 전체는 막지 않았다(`2334-1`, `1109-1` 이후 등은 유지). 팀 보고와 지도에 근거한 보수적 제외이며, 별도 현장 실측·로드뷰 검증은 하지 않았다. 카톡에 언급된 현장 사진 2장은 제공된 Notion 페이지에서 별도 첨부를 찾지 못해 직접 확인했다고 보고하지 않는다.

원인은 **데이터의 보행 속성 부족과 서버의 통행 가능 추정**이다. 최종 GPKG에는 `foot/access/sidewalk` 태그가 없고, 서버는 미군기지·계단·일부 차량 전용 유형을 제외한 일반 도로를 통행 가능으로 본다. 해당 구간의 `residential/tertiary/secondary` 유형은 이 필터를 통과했다. 탐색기는 허용된 간선을 정상적으로 선택했지만, 허용 여부의 입력 조건이 불충분했다. 모든 대로를 일괄 제외하면 실제 보도가 있는 도로도 사라지므로 검토된 간선만 제외했다.

| 추천 순번 | 검토 전 거리 / 비용 | 검토 후 거리 / 비용 |
|---|---|---|
| 1 | 5.112km / 5,834.65 | 5.112km / 5,834.65 |
| 2 | 4.699km / 5,398.66 | 5.363km / 6,210.09 |
| 3 | 4.658km / 5,209.67 | 5.327km / 6,072.86 |

후보 번호는 수정 전후에 같은 경로의 식별자가 아니다. 통행 조건 변경으로 후보 2·3이 새 경로로 선정되었다. 새 후보 3개 모두 제외 간선 4개를 포함하지 않는 것을 확인했다. 기존 4쌍×α 0·1·3·5 비교 실험도 다시 실행했으며, 이번 제외 구간을 이용하지 않아 수치는 이전과 같았다.

팀 자료에 추가로 적힌 추천 1의 39번·추천 3의 14번 코너는 별도 간선 식별·검토가 필요하다. 이번 조치로 모든 추천 코스의 보도·현장 통행이 검증됐다는 뜻은 아니다.

새 후보 2에는 기존 제외 간선과 다른 `1174-0`(서빙고지하차도, OSM 65388529)·`1904-0`(서빙고나들목) 등이 포함된다. 같은 지명이 있어도 같은 간선이라고 단정할 수 없으며, 이 대체 통로의 보행 가능 여부는 별도 확인이 필요하다. 새 후보 2를 현장 사용 가능 코스로 확정하지 않는다.

## 5. 재현과 검증

```sh
cd server
.venv/bin/python -m dalro_api.audit_quality --evidence data/audit-2026-11-18 --output data/audit-2026-11-18/report
.venv/bin/python -m pytest
cd ..
npm run check
node --import tsx scripts/validate-data.ts server/data/audit-2026-11-18/report/export
```

증빙 입력은 Notion 첨부에서 받은 엑셀 2개와 원본 검증 도로망 ZIP이며 `server/data/audit-2026-11-18/`에 보관한다. 원본·엑셀·생성 코스는 커밋하지 않는다. 감사 스크립트는 원본 DB를 읽기 전용으로 열고 seed를 별도 임시 DB에 복원하여 대조한다.

- 앱 `npm run check`: TypeScript·ESLint·Vitest 81개·예시 계약·명령 가드 통과.
- 서버 pytest 36개 통과. 버전·피처 식별·0과 결측 구분·검토 간선만 제외·캐시 무효화 회귀를 포함한다.
- 실제 고정 seed를 복원한 FastAPI에서 결측 42개 보정·4개 제외·새 추천 3개·이전 추천 2 상세 404 확인.
- 실제 서버 export의 도로 9,276개·추천 6개가 앱 계약 검사 통과.
- 웹·iOS·Android JS export 통과. 실제 APK/IPA 빌드·기기·GPS·현장 주행은 검증하지 않았다.
- 웹 E2E: 설치된 Chrome으로 모바일·데스크톱 19개 통과, 7개 제외(비활성 카카오 모드 6개, 데스크톱 터치 검사 1개).
- `npx expo install --check`: 네트워크 제한으로 로컬 SDK bundledNativeModules 기준 검사, 의존성 일치.

**커밋·push·배포는 하지 않았다. 현재 배포 버전은 여전히 `yongsan-verified-988cb48a`이므로, 실제 서비스 반영에는 앱과 서버를 함께 배포해야 한다.**
