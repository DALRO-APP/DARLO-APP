# 발표 피드백 반영: 패널티 표현과 추가 경로 실험

사용자가 전달한 중간 발표 피드백과 추가 경로 실험 요청을 반영했다. 원본 `pdf/`와 기존 파란색·초록색 발표 자료는 보존한다. 커밋·push·Vercel 배포는 수행하지 않는다. 전달 위치는 기존 [DALRO - 앱 구현 상황](https://app.notion.com/p/4098ae567af280c299a5e28367249f33)이다.

## 앱과 API

- 추천·상세·결과 화면: 환경 점수 대신 **환경 패널티**, 범위 0~1, 낮을수록 좋음을 표시한다.
- 새 `summary.environment_penalty`는 `Σ(구간 길이×구간 패널티)/Σ구간 길이`다. 서버는 반올림 전 값을 반환하고 화면만 소수 셋째 자리로 표시한다.
- `environment_score = round(100×(1−패널티))`는 새 응답과 더미에서 제거했다. `95`를 `패널티 95`로 표시하거나 옛 정수 점수로 정밀 패널티를 역산하지 않는다.
- Zod와 Pydantic은 필드가 없는 이전 코스·기기 캐시·서버 저장 코스를 패널티 `null`로 읽는다. 기존 경로와 상세 URL은 유지한다. 이전 모의 기록에 필드가 없어도 결과 화면에서 ‘미확인’으로 표시한다. 구버전 HTTP 서버와 함께 실행하면 새 필드는 미확인이다. 새 앱과 새 서버를 함께 적용해야 수치가 표시된다.
- mock/http 계약을 함께 변경했다. 더미의 패널티도 명시적 시연 값이며 실데이터에서 계산한 값으로 취급하지 않는다.
- 경로 비용 `C(e)=길이×(1+α×p)`와 구간 패널티 `p=0.83×stop_norm+0.17×slope_norm`은 그대로 유지한다.
- 내부 후보 정렬 속성 `score`는 `selection_cost`로 변경했다. 식은 기존과 같은 `Cost/거리 + 반복 비율 + 0.5×|거리 오차|`다. 선정 비용은 단위 없는 비교값이고, 경로 비용은 거리 환산 값이다. 실제 주행 거리·측정된 체감 거리가 아니다.
- 입력·즐겨찾기 상태와 CourseRepository/Query 경계를 유지한다. α 조절 화면은 추가하지 않았다. 실험용 `Overlay.search(..., alpha=...)`는 기본값 3이며 요청마다 그래프를 바꾸지 않는다.

## 발표 자료

- 본문 계산 설명은 **멈춤·경사 정보 → 환경 패널티 → 거리와 함께 경로 탐색**의 3단계로 줄인다.
- 정규화 5단계와 AHP 표는 부록으로 분리한다. 0.83/0.17과 α=3은 기존 팀 설정을 유지하며 새 최적값으로 주장하지 않는다.
- Final score/최종 점수는 **선정 비용(낮을수록 우선)**으로 바꾼다. 환경 패널티·경로 비용·선정 비용의 의미를 분리한다.
- 도로 패널티는 주황 순차색(진할수록 큼), 추천 경로는 초록 실선으로 분리하고 범례에 명시한다. 경로 색을 ‘좋고 나쁨’의 순차 범례로 해석하지 않게 한다.
- 현재 로컬 웹과 고정 seed에서 복원한 임시 FastAPI 서버의 실제 HTTP 추천으로 앱 화면을 다시 캡처한다. 실데이터 추천과 모의 러닝을 구분하며, 기존 배포 사이트 캡처라고 표시하지 않는다.
- 기존 10장 수정 + 추가 실험 요약 1장 + 추가 장소쌍별 3장 + 상세 공식 부록 1장으로 15장이다. PPTX는 기존 전달 방식과 같은 이미지 슬라이드이며 개별 텍스트 편집 파일은 아니다.
- 기존 후보 6개 비교와 Dijkstra/A* 확정 노드 수는 동일 도로망·변하지 않은 비용식의 이전 계산 자료를 재사용했다. 이번에 재실행한 경로 비교와 구분한다.

## 추가 실험

자료 버전: `yongsan-verified-988cb48a`. 기존 1쌍과 사전에 고정한 추가 3쌍에서 α=0·1·3·5를 비교했다. 원본 SQLite를 읽기 전용으로 열고 코스나 추천 로그를 저장하지 않는다. 결과에 유리한 장소쌍만 고르지 않는다.

| 장소쌍 | 최단거리 → α=3 | 거리 증가 | 신호 부착대+횡단보도 | 시설 합계 변화 |
|---|---|---:|---|---|
| 기존: 이촌 한강공원 → 남산 둘레길 | 6.593 → 6.740km | +2.2% | 90 → 54 | 40.0% 감소 |
| 추가 1: 이촌 한강공원 → 용산가족공원 | 1.942 → 1.967km | +1.3% | 23 → 18 | 21.7% 감소 |
| 추가 2: 용산가족공원 → 남산 둘레길 | 5.321 → 5.480km | +3.0% | 73 → 38 | 47.9% 감소 |
| 추가 3: 어린이공원(삼각지) → 이촌 한강공원 | 2.887 → 2.910km | +0.8% | 46 → 47 | 2.2% 증가 |

시설 수는 앱과 같은 **경로 10m 버퍼 안 종류별 고유 시설 수**다. 동일 시설을 여러 구간에서 지나도 경로 집계에서는 한 번 센다. 신호 부착대 수는 실제 교차로나 정지 횟수가 아니다. 비용식의 구간 밀도 합성과 경로의 고유 시설 집계는 서로 다른 양이므로, 패널티가 낮아져도 시설 합계가 늘 수 있다. 실제로 추가 3은 평균 패널티가 0.0744→0.0639로 낮아졌지만 횡단보도 수가 늘었다.

추가 3쌍 중 2쌍에서 시설 합계가 감소했다. 사례들이 도로를 공유하고 표본도 작으므로 독립적인 통계 검증이나 일반적인 효과로 주장하지 않는다. 지형 경사는 노면 경사가 아니며 미측정은 최대 경사 패널티를 적용한다. GPS 주행·신호 대기 시간·현장 통행·안전성은 검증하지 않았다.

## 실행과 전달

```sh
cd server
.venv/bin/python -m dalro_api.experiment --output ../artifacts/DALRO-feedback-2026-11-17
cd ..
EXPO_PUBLIC_DATA_SOURCE=http EXPO_PUBLIC_API_URL=http://127.0.0.1:18787 npx expo export --platform web --clear --output-dir artifacts/DALRO-feedback-2026-11-17/web
node scripts/capture-feedback.mjs
python scripts/build-feedback-presentation.py --output artifacts/DALRO-feedback-2026-11-17
```

발표 생성 Python에는 matplotlib·python-pptx·Pillow가 필요하다. 이번 실행은 `/private/tmp/dalro-feedback-venv`를 사용했다. 환경변수 변경 후 export의 `--clear`는 Metro의 이전 환경값 캐시를 제거한다. 일반 웹 시연은 `npm run export:web` 후 `node scripts/serve-demo.mjs`로 실행한다.

로컬 전달 폴더 `artifacts/DALRO-feedback-2026-11-17/`:

- `SLIDES/`, `PNG/`: 슬라이드와 개별 시각 요소.
- `DALRO_feedback_2026-11-17.pptx`, `DALRO_feedback_all.zip`, `DALRO_feedback_PNG.zip`.
- `experiments.csv`, `routes.geojson`, `experiment-report.md`: 모든 α의 표·경로·해석.
- `source/`: 재생성 코드·계산 파생 자료·현재 앱 캡처. SQLite·원본 zip·비밀값은 포함하지 않는다.

## 검증

- `npm run check`: TypeScript·ESLint·Vitest 78개·예시 자료 계약·명령 가드 통과. 생성된 웹 번들은 ESLint의 `artifacts/**` 제외 대상에 추가했다.
- 서버 pytest 32개 통과. 구간 패널티 길이 가중 평균, 구버전 점수 미역산, α별 A*/Dijkstra 최소 비용 일치, 원본 그래프 불변, 시설 미측정·0의 감소율 처리 등을 확인했다.
- `npm run export:web`, `npm run export:ios`, `npm run export:android` 통과. `npx expo install --check`는 온라인 조회가 제한되어 로컬 `bundledNativeModules.json`을 사용했으며 일치한다.
- `PLAYWRIGHT_CHROME=1 npx playwright test`: 모바일·데스크톱 19개 통과, 7개 제외. 비활성 카카오 모드의 6개와 데스크톱에 적용되지 않는 터치 검사 1개다. Playwright 전용 Chromium이 없어 설치된 Chrome을 사용했다.
- 실데이터 HTTP 임시 서버에서 현재 앱의 추천→상세→모의 러닝→결과를 별도 실행했다. 브라우저 오류 0, 화면 6개를 캡처했다. 원래 8787 포트는 다른 프로세스가 사용 중이어서 건드리지 않고 별도 18787 포트를 사용했다.
- 슬라이드 15장 1920×1080, PPTX 15장, 개별 PNG 25개, ZIP CRC 무결성을 확인했다. 계산 설명·지도·후보 비교·실험 요약·증가 사례·부록과 실제 추천 화면을 직접 이미지로 확인했다.
- 네이티브 JS export는 APK/IPA 빌드나 실제 기기 검증이 아니다. 실제 휴대폰·GPS·현장 주행·PowerPoint 앱 직접 열기는 검증하지 않았다.

- 첫 `update_content`는 본문 텍스트·표에는 적용됐지만 이미지와 파일 블록에는 `no_match` 경고가 발생했다. 현재 내용을 다시 읽고 관련 수정만 합친 전체 본문으로 교체했다. 최종 저장은 오류·경고 없이 완료됐고, 이미지·파일·0.047 패널티·46→47 증가 사례·모든 α의 표가 저장됐음을 다시 조회했다. 페이지 패널 도구도 호출했다.
- 커밋·push·Vercel 배포·팀원 메시지 전송은 하지 않았다. 기존 사용자 변경과 원본 `pdf/`, 기존 발표 산출물을 보존했다.
