# SQLite 손상 복구 확인

2026-10-28. 이전 작업에서 추가한 임포터의 손상 DB 보관·기록 복원 기능을 확인했다.

- 현재 `server/data/dalro.sqlite3`의 읽기 전용 `PRAGMA quick_check` 결과는 `ok`다.
- 확인 시점에 코스 73개, 추천 기록 57개, 도로 구간 9,276개, 노드 6,906개, 검색 장소 15,682개가 있다.
- 손상 DB와 보조 파일은 `server/data/corrupt-20261028-192828/`에 남아 있다. 이번 확인에서 현재 DB나 보조 파일을 이동·삭제하거나 재임포트하지 않았다.
- 임포터는 손상 여부를 검사하고 읽을 수 있는 `courses`, `recommendation_logs`를 보존한 뒤 원본 도로망을 다시 임포트한다. 복구 테스트를 포함한 서버 pytest 20개가 통과했다.
- 손상 DB 보관 폴더도 Git 제외 대상에 추가했다. 원본 zip과 DB는 커밋하지 않는다.
- 실행 중인 로컬 서버 `http://127.0.0.1:8000`의 `/health`는 `ok`다. 검색은 카카오 키 없는 `local` 모드이며, 강남은 범위 밖·이촌은 범위 안으로 응답했다.
- 이촌 한강공원 5km PACE Loop 요청에서 실데이터 코스 3개(5,112m·4,699m·4,658m)를 받았고 상세 조회도 성공했다. 이 확인으로 코스·추천 기록이 추가될 수 있다.
- `npm run check` 통과: 타입 검사, lint, 앱 테스트 63개, 데이터 계약 검사, 명령 가드 검사. 이번 작업에서는 웹 E2E·native 빌드·실기 검증을 수행하지 않았다.

복구나 재임포트 전에는 해당 DB를 사용하는 서버를 종료한다. 실행 중인 SQLite의 WAL/SHM 파일을 직접 삭제하지 않는다. 복원은 읽을 수 있는 기록에 한하며, 손상된 기록까지 복구를 보장하지 않는다.
